# 模型路由策略

每次创建子 Agent 前都执行本策略。目标是选择能够可靠完成任务的最低成本模型，而不是让所有角色都使用最强模型。

## 第一步：取得可用模型

只使用当前 `spawn_agent` 工具或运行时明确列出的模型 ID 与推理强度。不要根据旧文档、记忆或示例猜测模型是否可用。

如果运行时没有暴露模型覆盖能力：

- 省略 `model` 和 `reasoning_effort` 参数，让子 Agent 继承主 Agent。
- 在 TaskSpec 中填写 `model: inherit` 并说明原因。
- 仍然进行任务分级，以便运行时能力恢复后能够直接映射。

用户明确指定模型或推理强度时，优先遵循用户要求；若当前运行时不支持，必须明确报告，不能静默替换。

## 第二步：确定角色默认档位

| 角色 | 默认档位 | 默认推理强度 | 适用说明 |
| --- | --- | --- | --- |
| `explorer` | fast | low | 搜索、清点和收集直接证据 |
| `worker` | balanced | medium | 边界明确的普通代码实现 |
| `specialist` | strongest | high | 架构、疑难根因或高风险改动 |
| `reviewer` | balanced | medium | 普通独立审查 |
| `tester` | fast | low | 执行已有构建、测试或 UI 检查 |

角色只提供起点，最终选择由具体 TaskSpec 决定。

## 第三步：按任务升降档

分别评估以下四项，每项取值为 `0`、`1` 或 `2`：

- `complexity`：机械操作为 0；需要多步推理为 1；涉及架构或复杂状态为 2。
- `ambiguity`：输入和目标明确为 0；存在少量未知为 1；根因或方案未知为 2。
- `risk`：容易回滚为 0；可能引起局部回归为 1；安全、数据或广泛兼容风险为 2。
- `breadth`：单个局部区域为 0；跨两个模块为 1；跨多个系统或平台为 2。

合计分数用于修正默认档位：

| 总分 | 建议档位 | 建议推理强度 |
| --- | --- | --- |
| 0–2 | fast | low |
| 3–5 | balanced | medium |
| 6–7 | strongest | high |
| 8 | strongest | xhigh（运行时支持时） |

应用以下下限和例外：

- `specialist` 不低于 strongest；特别简单的任务不应创建 `specialist`，而应改用其他角色。
- 涉及安全、数据丢失、公共 API 兼容或大规模迁移的 `reviewer` 使用 strongest/high。
- `tester` 仅执行已知命令时使用 fast/low；需要诊断复杂失败时升为 balanced/medium，若要修改代码则结束测试任务并重新分配。
- 机械且可独立验证的 `worker` 可以降为 fast/low。
- 高档位不能弥补含糊的 TaskSpec；应先缩小任务边界，再决定是否升级模型。

## 第四步：映射为实际模型

根据当前运行时提供的模型描述进行映射：

- `fast`：选择描述为快速、低成本或适合简单子任务的可用模型。
- `balanced`：选择描述为日常编码、均衡或可靠工作负载的可用模型。
- `strongest`：选择描述为最强、复杂任务或高难度推理的可用模型。

同一档位存在多个候选时，优先选择更符合任务类型的模型；没有足够信息时继承主 Agent，而不是随意猜测。不要把示例模型名称写入角色文件，以免模型更新后路由失效。

## 第五步：记录并调用

在 TaskSpec 的 `model_route` 中记录：

```yaml
model_route:
  tier: balanced
  model: 运行时实际模型 ID
  reasoning_effort: medium
  reason: 普通跨文件实现，边界清晰但需要保持行为兼容
```

调用 `spawn_agent` 时：

- `model` 使用上述实际模型 ID。
- `reasoning_effort` 使用该模型明确支持的值。
- 显式设置 `model` 或 `reasoning_effort` 时，`fork_turns` 必须设为 `none` 或有限的正整数，不能使用完整历史继承。
- 若继承主 Agent，则省略这两个覆盖参数，并可根据任务需要决定上下文传递量。
- `fork_turns` 只决定上下文传递量，不用于表达模型能力；无论取值如何，TaskSpec 和角色边界都应在任务消息中完整提供。

模型路由失败不应阻塞整个任务：记录降级原因，使用最接近的可用档位或继承主 Agent，并继续执行范围明确的工作。
